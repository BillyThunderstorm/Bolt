## 4. The workflow (one loop)

Use this as the only default until it feels boring (boring = good).

### Stage A — Pick (5 minutes)
1. Choose **one** owned item or game session already in your world.  
2. Write one honest angle: *what you’re testing + one real question*  
   - Example: “Daily driver headset — is the mic clear enough for Twitch without sounding compressed?”  
3. Pick **one primary platform** for the first cut (TikTok **or** YouTube Shorts **or** Twitch clip). Repurpose second.

**Rule:** If you own it and used it this week, it’s eligible. No “wait for perfect product.”

### Stage B — Capture (15–40 minutes)
1. Phone or existing setup only — no new gear required to start.  
2. Record: problem → using it → honest take (good + bad).  
3. Get 1 clean hook line on camera or as voiceover later:  
   - “I used this for X hours. Here’s what actually mattered.”  
4. Save raw files to one place every time (example):  
   `Content/Inbox/YYYY-MM-DD_topic/`

### Stage C — Edit light (20–40 minutes)
1. Hard rule: **under 60 seconds** for first short-form cut unless it’s a Twitch moment.  
2. Structure: Hook (0–3s) → proof (use clip) → honest verdict → soft CTA (“want full setup?” / “should I test mic vs Y?”).  
3. Text on screen for silent watchers.  
4. Export presets: one vertical 1080x1920. Stop there for v1.

### Stage D — Package (10 minutes)
For the chosen platform, prep only:
- Caption (plain, not hype)
- 3–8 hashtags max **or** none if they feel forced
- Affiliate only if relevant and honest: Amazon tag `billycarter-20`
- Screenshot thumbnail frame if needed

**Caption skeleton:**  
What you tested + one true finding + one question for comments.

### Stage E — Approve & post (you gate this)
1. You watch once.  
2. Approve or request one fix.  
3. Post manually (or approve Bolt’s draft copy — still your send).  
4. Log it (see below).

### Stage F — Sync / log (5 minutes)
Same note every time:
- What posted + platform  
- Angle  
- What felt true / what felt fake  
- One keep / one change  
- Views later (24–48h) — no obsessing day-of  

This log is how the workflow improves without random restarts.
